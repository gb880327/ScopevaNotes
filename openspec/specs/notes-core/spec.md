# notes-core Specification

## Purpose
定义笔记的唯一数据模型与读写语义：一条笔记即一份 Markdown 文本，可带多个标签、可收藏、可软删除恢复，并在多端触发保存时保持一致。

## Requirements

### Requirement: 笔记数据模型

系统 MUST 只提供一种内容实体 `Note`，包含稳定 id、标题、Markdown 正文、收藏标记、创建时间、更新时间与零到多个标签；MUST NOT 引入独立的代码片段实体或第三栏视图。id MUST 为 UUIDv7，时间戳 MUST 为 Unix 毫秒（UTC）。

#### Scenario: 创建笔记只产生一个实体
- **WHEN** 用户新建笔记并输入标题与正文
- **THEN** 数据库只新增一条 `notes` 记录与其关联的 `note_tags` 记录，不产生片段或附件记录

#### Scenario: 空正文合法
- **WHEN** 用户新建笔记后立即保存且未输入任何正文字符
- **THEN** 保存成功，笔记以空正文存在于列表中，标题为空时以「无标题」呈现

### Requirement: 笔记列表返回摘要

列表接口 MUST 只返回摘要字段（id、标题、摘要片段、更新时间、收藏、标签），MUST NOT 返回完整正文。MUST 支持游标分页，默认页大小 MUST 为 50，且顺序 MUST 为收藏优先、更新时间倒序稳定排列。

#### Scenario: 列表不含正文
- **WHEN** 前端请求首页笔记列表
- **THEN** 每项只含摘要字段，正文仅在打开单条笔记时通过详情接口获取

#### Scenario: 加载更多不重复
- **WHEN** 用户滚动到底部触发加载下一页
- **THEN** 追加的记录不含上一页已出现的 id，且顺序与数据库排序一致

### Requirement: 乐观并发更新

更新笔记 MUST 校验调用方携带的 `expectedUpdatedAt`；与库中当前更新时间不一致时 MUST 返回冲突错误且不写入，MUST NOT 静默覆盖。

#### Scenario: 过期版本被拒绝
- **WHEN** 笔记已被另一路径更新，随后带着旧 `expectedUpdatedAt` 提交保存
- **THEN** 接口返回冲突错误，正文保持为库中的较新版本

#### Scenario: 正常更新刷新时间戳
- **WHEN** 携带与库一致的 `expectedUpdatedAt` 提交新正文
- **THEN** 正文与 `updatedAt` 一并更新，返回的 `updatedAt` 大于此前值并与列表排序位置一致

### Requirement: 自动保存

编辑器 MUST 在停止输入约 600ms 后自动保存，MUST 串行执行保存请求，且 MUST 保证较早的请求返回时不会覆盖较新的本地内容。切换笔记、隐藏窗口、打开设置或切换笔记库前 MUST 先 flush 未落盘内容。保存失败 MUST 在界面上呈现未保存状态并保留待重试内容。

#### Scenario: 连续输入只落最后内容
- **WHEN** 用户快速输入触发多次防抖保存
- **THEN** 保存请求按顺序执行，数据库最终内容等于编辑器最后一次输入

#### Scenario: 旧请求回包不覆盖新输入
- **WHEN** 保存进行中用户继续输入，旧请求随后返回成功
- **THEN** 编辑器保留新输入，仅更新已保存版本号，界面继续显示待保存

#### Scenario: 切换笔记前落盘
- **WHEN** 存在未 flush 的编辑时用户点击另一条笔记
- **THEN** 系统先完成当前笔记保存，再加载并显示目标笔记

#### Scenario: 保存失败可见
- **WHEN** 保存因数据库错误失败
- **THEN** 界面显示未保存/重试状态，内容仍留在编辑器中，不被回滚为空

### Requirement: 收藏与软删除恢复

收藏 MUST 可独立于正文更新切换。删除 MUST 为软删除：记录保留并带删除时间，MUST 从列表与搜索中消失，MUST 可由恢复操作还原为正常笔记。

#### Scenario: 收藏不改变正文时间
- **WHEN** 用户点击收藏
- **THEN** 仅收藏标记变化，标题、正文与 `updatedAt` 不变

#### Scenario: 删除后不可见
- **WHEN** 用户删除一条笔记
- **THEN** 该笔记不再出现在列表、搜索与标签计数中，且不进入 FTS 索引

#### Scenario: 恢复还原笔记
- **WHEN** 用户恢复一条已软删除笔记
- **THEN** 笔记重新出现在列表与搜索中，原文与标签保持完整

### Requirement: 标签管理

标签名 MUST 先归一化（去首尾空白、压缩内部连续空白），MUST 大小写不敏感唯一。标签 MUST 支持重命名与删除，且 MUST 维护笔记关联与搜索索引；删除标签 MUST NOT 删除笔记。

#### Scenario: 大小写重复被拒绝
- **WHEN** 已存在 `Rust` 标签时用户创建 `rust`
- **THEN** 系统返回冲突错误且不新增标签

#### Scenario: 重命名同步索引
- **WHEN** 用户将标签 `db` 重命名为 `database`
- **THEN** 关联笔记仍保留该标签，按新名称可检索到这些笔记

#### Scenario: 删除标签保留笔记
- **WHEN** 用户删除一个被 3 条笔记使用的标签
- **THEN** 3 条笔记仍存在且正文不变，仅失去该标签关联

### Requirement: 标签列表带计数

标签列表 MUST 返回每个标签的可见笔记数量（不含软删除笔记），且 MUST NOT 为每个标签单独发起查询。

#### Scenario: 计数排除已删除笔记
- **WHEN** 某标签关联 2 条笔记，其中 1 条被软删除
- **THEN** 标签列表显示该标签计数为 1
