# notes-core Specification

## Purpose
定义笔记的唯一数据模型与读写语义：一条笔记即一份 Markdown 文本，可带多个标签、可收藏、可软删除恢复，并在多端触发保存时保持一致。

## Requirements

### Requirement: 笔记数据模型

系统 MUST 只提供一种笔记内容实体 `Note`，包含稳定 id、标题、Markdown 正文、收藏标记、创建时间、更新时间与零到多个标签；MUST NOT 引入独立的代码片段实体或第三栏视图。id MUST 为 UUIDv7，时间戳 MUST 为 Unix 毫秒（UTC）。

唯一的限定例外是**速记（Quick Tab）**：它是独立于 `Note` 的第二实体，MUST 与笔记体系完全隔离——MUST NOT 存储于 `notes`、`notes_fts` 或 `note_tags`，MUST NOT 支持标签，MUST NOT 出现在笔记列表、搜索结果、标签计数、回收站或导入批次中，MUST NOT 提供任何自动或半自动进入笔记体系的通道（含「转换为笔记」）。速记的语义由 `quick-tabs` capability 定义，本条只约束边界：`Note` 的字段、软删除与恢复、标签、回收站语义不因速记存在而改变。

#### Scenario: 创建笔记只产生一个实体
- **WHEN** 用户新建笔记并输入标题与正文
- **THEN** 数据库只新增一条 `notes` 记录与其关联的 `note_tags` 记录，不产生片段或附件记录

#### Scenario: 空正文合法
- **WHEN** 用户新建笔记后立即保存且未输入任何正文字符
- **THEN** 保存成功，笔记以空正文存在于列表中，标题为空时以「无标题」呈现

#### Scenario: 速记不扩张笔记实体
- **WHEN** 用户创建并编辑若干速记后打开笔记列表与搜索
- **THEN** 列表与搜索结果只包含 `notes` 中的内容，速记既不出现在列表也不影响标签计数

### Requirement: 笔记列表返回摘要

列表接口 MUST 只返回摘要字段（id、标题、摘要片段、更新时间、收藏、标签），MUST NOT 返回完整正文。MUST 支持游标分页，默认页大小 MUST 为 50，且顺序 MUST 为收藏优先、更新时间倒序稳定排列。

#### Scenario: 列表不含正文
- **WHEN** 前端请求首页笔记列表
- **THEN** 每项只含摘要字段，正文仅在打开单条笔记时通过详情接口获取

#### Scenario: 加载更多不重复
- **WHEN** 用户滚动到底部触发加载下一页
- **THEN** 追加的记录不含上一页已出现的 id，且顺序与数据库排序一致

### Requirement: 乐观并发更新

更新笔记 MUST 校验调用方携带的 `expectedUpdatedAt`；与库中当前更新时间不一致时 MUST 返回冲突错误且不写入，MUST NOT 静默覆盖。

#### Scenario: 过期版本被拒绝
- **WHEN** 笔记已被另一路径更新，随后带着旧 `expectedUpdatedAt` 提交保存
- **THEN** 接口返回冲突错误，正文保持为库中的较新版本

#### Scenario: 正常更新刷新时间戳
- **WHEN** 携带与库一致的 `expectedUpdatedAt` 提交新正文
- **THEN** 正文与 `updatedAt` 一并更新，返回的 `updatedAt` 大于此前值并与列表排序位置一致

### Requirement: 自动保存

编辑器 MUST 在停止输入约 600ms 后自动保存，MUST 串行执行保存请求，且 MUST 保证较早的请求返回时不会覆盖较新的本地内容。切换笔记、隐藏窗口、打开设置或切换笔记库前 MUST 先 flush 未落盘内容。保存失败 MUST 在界面上呈现未保存状态并保留待重试内容。

#### Scenario: 连续输入只落最后内容
- **WHEN** 用户快速输入触发多次防抖保存
- **THEN** 保存请求按顺序执行，数据库最终内容等于编辑器最后一次输入

#### Scenario: 旧请求回包不覆盖新输入
- **WHEN** 保存进行中用户继续输入，旧请求随后返回成功
- **THEN** 编辑器保留新输入，仅更新已保存版本号，界面继续显示待保存

#### Scenario: 切换笔记前落盘
- **WHEN** 存在未 flush 的编辑时用户点击另一条笔记
- **THEN** 系统先完成当前笔记保存，再加载并显示目标笔记

#### Scenario: 保存失败可见
- **WHEN** 保存因数据库错误失败
- **THEN** 界面显示未保存/重试状态，内容仍留在编辑器中，不被回滚为空

### Requirement: 收藏与软删除恢复

收藏 MUST 可独立于正文更新切换。删除 MUST 为软删除：记录保留并带删除时间，MUST 从列表与搜索中消失，MUST 可由恢复操作还原为正常笔记。

#### Scenario: 收藏不改变正文时间
- **WHEN** 用户点击收藏
- **THEN** 仅收藏标记变化，标题、正文与 `updatedAt` 不变

#### Scenario: 删除后不可见
- **WHEN** 用户删除一条笔记
- **THEN** 该笔记不再出现在列表、搜索与标签计数中，且不进入 FTS 索引

#### Scenario: 恢复还原笔记
- **WHEN** 用户恢复一条已软删除笔记
- **THEN** 笔记重新出现在列表与搜索中，原文与标签保持完整

### Requirement: 标签管理

标签名 MUST 先归一化（去首尾空白、压缩内部连续空白），MUST 大小写不敏感唯一。标签 MUST 支持重命名与删除，且 MUST 维护笔记关联与搜索索引；删除标签 MUST NOT 删除笔记。

#### Scenario: 大小写重复被拒绝
- **WHEN** 已存在 `Rust` 标签时用户创建 `rust`
- **THEN** 系统返回冲突错误且不新增标签

#### Scenario: 重命名同步索引
- **WHEN** 用户将标签 `db` 重命名为 `database`
- **THEN** 关联笔记仍保留该标签，按新名称可检索到这些笔记

#### Scenario: 删除标签保留笔记
- **WHEN** 用户删除一个被 3 条笔记使用的标签
- **THEN** 3 条笔记仍存在且正文不变，仅失去该标签关联

### Requirement: 标签列表带计数

标签列表 MUST 返回每个标签的可见笔记数量（不含软删除笔记），且 MUST NOT 为每个标签单独发起查询。

#### Scenario: 计数排除已删除笔记
- **WHEN** 某标签关联 2 条笔记，其中 1 条被软删除
- **THEN** 标签列表显示该标签计数为 1

### Requirement: 标签管理（侧栏就地编辑）

标签列表 MUST 同时充当标签的管理入口：列表 MUST 展示全部标签的名称、颜色与可见笔记数，并 MUST 允许在列表内直接完成重命名、改色与删除，MUST NOT 要求用户离开列表或打开独立窗口。点击标签行本身 MUST 仍然是按该标签过滤笔记，编辑动作 MUST 由行内独立控件触发，不得与过滤手势混淆。标签过滤 MUST 为单选：任意时刻至多一个标签处于选中状态，选中另一个标签 MUST 替换当前选中而不是叠加，再次点击已选中的标签 MUST 清除该过滤。新增与重命名 MUST 沿用既有的归一化与大小写不敏感唯一规则：重名 MUST 返回可见冲突错误而不是静默合并，空名称 MUST NOT 创建或改名。删除 MUST 在该行内显示将被摘除关联的可见笔记数并要求确认；删除 MUST NOT 删除任何笔记，也 MUST NOT 影响这些笔记的正文与时间戳。任一操作失败后 MUST NOT 留下部分更新（标签未改、关联未动、列表与计数保持原状）。

#### Scenario: 侧栏就地重命名
- **WHEN** 用户在侧栏把标签 `db` 重命名为 `database`
- **THEN** 该行就地显示新名称，笔记上的标签 chip 与按 `database` 的搜索结果同时反映新名称，原名称不再出现在标签列表中

#### Scenario: 点击行仍然只是过滤
- **WHEN** 用户点击标签行名称区域
- **THEN** 列表按该标签过滤，不会进入编辑状态、也不会弹出删除确认

#### Scenario: 标签过滤是单选
- **WHEN** 用户点击标签 `rust` 后再点击标签 `db`
- **THEN** 只有 `db` 处于选中状态、列表只按 `db` 过滤，`rust` 不再选中；再点一次 `db` 则清除该过滤并回到未按标签过滤的列表

#### Scenario: 删除标签先确认再摘除
- **WHEN** 用户在侧栏删除一个被 3 条可见笔记使用的标签
- **THEN** 该行先提示将影响 3 条笔记，确认后这 3 条笔记仍存在、正文与时间戳不变、仅失去该标签，行内计数与过滤结果立即更新

#### Scenario: 重名被拒绝并保留原状态
- **WHEN** 已存在 `Rust` 时用户在侧栏把 `db` 重命名为 `rust`
- **THEN** 该行显示冲突错误并保留 `db`，列表不出现 `rust`，原有关联不变

#### Scenario: 空名称不改动标签
- **WHEN** 用户在新建或重命名输入框里提交只含空白字符的名称
- **THEN** 系统不创建、也不改名，列表保持原状

### Requirement: 笔记标签编辑

笔记头部 MUST 展示该笔记当前标签，并 MUST 允许用户为当前笔记添加已有标签、输入新名称新建并立即挂上该笔记、以及摘除某个标签。标签变更 MUST 走与正文相同的保存路径（含乐观并发与自动保存），MUST 在保存成功后立即反映到标签列表计数与搜索结果；保存失败 MUST 显示可见错误并保留用户这次操作的结果（不得静默丢弃，也不得只在下次刷新时消失）。

#### Scenario: 添加已有标签
- **WHEN** 用户在笔记头部选择一个已存在的标签
- **THEN** 该标签出现在笔记标签区，标签列表中该标签的计数加一，按该标签过滤能命中这条笔记

#### Scenario: 输入新名称即建即挂
- **WHEN** 用户在笔记头部输入一个不存在的标签名并确认
- **THEN** 系统新建该标签并立即挂到当前笔记，同时出现在标签管理界面中

#### Scenario: 摘除只影响本笔记
- **WHEN** 用户从一条笔记上摘除标签 `work`，而 `work` 仍被其它笔记使用
- **THEN** 仅这条笔记失去该标签，其它笔记的关联与标签本身都保留

#### Scenario: 保存失败时可见且不丢输入
- **WHEN** 标签变更因版本冲突或数据库错误保存失败
- **THEN** 界面显示可读错误，用户刚添加或摘除的标签状态保留在界面上，不会静默回滚

### Requirement: 永久删除

系统 MUST 支持把一条已在回收站的笔记永久删除，以及一次性清空回收站。永久删除 MUST 只由用户显式触发（单条删除或清空），且 MUST 先显示将删除的条数与"不可恢复"提示并要求确认；取消确认 MUST NOT 删除任何数据。永久删除 MUST 在同一事务内移除该笔记的正文、标签关联与搜索索引条目，且 MUST NOT 影响任何未删除笔记。永久删除 MUST NOT 提供撤销。导入批次撤销与普通删除 MUST 仍然只进回收站，任何自动流程 MUST NOT 永久删除。

#### Scenario: 单条永久删除
- **WHEN** 用户在回收站对一条笔记确认永久删除
- **THEN** 该笔记从回收站消失、正文与标签关联被删除、按其中关键词搜索不到，库中不再有这条记录

#### Scenario: 清空垃圾箱
- **WHEN** 用户在回收站确认清空
- **THEN** 回收站中全部笔记被永久删除，回收站显示空态，未删除笔记的数量、内容与时间戳保持不变

#### Scenario: 取消确认不删除
- **WHEN** 用户在永久删除或清空的确认框上选择取消
- **THEN** 回收站内容与笔记总数不变，不发出任何删除请求

#### Scenario: 永久删除后释放导入来源
- **WHEN** 用户永久删除一条由 Markdown 导入产生的笔记，随后再次导入同一目录
- **THEN** 该文件被重新导入为新笔记（软删除状态下则仍被跳过）

### Requirement: 回收站视图

回收站 MUST 以列表形式展示已删除笔记的标题、摘要、标签与删除时间，MUST 显示当前条数，并 MUST 为每条提供恢复与永久删除两个操作，同时 MUST 提供清空垃圾箱入口。已删除笔记 MUST NOT 进入普通列表、搜索与标签计数。回收站为空时 MUST 显示空态而不是空列表。

#### Scenario: 回收站展示删除时间
- **WHEN** 用户打开回收站且其中有 3 条笔记
- **THEN** 列表显示 3 条、条数为 3，每条都显示删除时间，可按删除时间倒序阅读

#### Scenario: 恢复后回到普通列表
- **WHEN** 用户在回收站对一条笔记点击恢复
- **THEN** 该笔记从回收站消失并出现在普通列表与搜索结果中，条数减一

#### Scenario: 空回收站显示空态
- **WHEN** 回收站中没有任何笔记（从未删除或刚刚清空）
- **THEN** 界面显示空态提示，不显示清空按钮为可用状态
