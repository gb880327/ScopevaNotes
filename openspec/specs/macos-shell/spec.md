# macos-shell Specification

## Purpose
定义应用在 macOS 上的窗口与常驻行为：一个主窗口、菜单栏入口、全局快捷键唤出，以及关闭窗口不退出程序的完整显隐语义。

## Requirements

### Requirement: 单主窗口

应用 MUST 只维护一个主笔记窗口，外加一个速记面板窗口（label `quick-tabs`，语义见 `quick-tabs` capability），MUST NOT 存在第三种窗口或窗口实例。主窗口默认尺寸 1100×720，最小尺寸 760×480，MUST 居中显示且 MUST 带原生窗口控制按钮。全局快捷键与界面内部操作 MUST 复用主窗口；菜单栏右键菜单与重复启动 MUST 唤出主窗口；菜单栏左键 MUST 只切换速记面板。速记面板的存在 MUST NOT 改变主窗口的尺寸、定位、置顶与显隐规则。

#### Scenario: 连按快捷键只有一个窗口
- **WHEN** 连续 100 次触发全局快捷键
- **THEN** 系统中始终只存在一个主窗口，无重复实例或残留幽灵窗口

#### Scenario: 速记面板不复制主窗口
- **WHEN** 用户连续 100 次点击菜单栏图标左键
- **THEN** 系统中始终只有一个速记面板实例，且主窗口显隐状态不变

#### Scenario: 尺寸受最小约束
- **WHEN** 用户把窗口缩小到极限
- **THEN** 宽高不低于 760×480，布局不出现内容溢出或控件不可达

### Requirement: 关闭即隐藏

点击窗口关闭按钮 MUST 隐藏窗口而不退出进程，MUST 保留 WebView 与未保存状态；只有经确认的退出动作 MUST 结束进程。

#### Scenario: 关闭按钮隐藏
- **WHEN** 用户点击关闭按钮
- **THEN** 窗口消失但应用仍在菜单栏运行，再次唤出时内容与滚动位置保持

### Requirement: 启动不显示主窗口

应用 MUST 以隐藏状态启动：进程启动、菜单栏图标出现、数据库与前端就绪后 MUST NOT 自动显示主窗口。用户 MUST 能通过菜单栏或全局快捷键唤出。首次运行的说明 MUST 从菜单栏侧（一次性提示或引导）给出，MUST NOT 依赖自动弹出主窗口。

#### Scenario: 冷启动保持隐藏
- **WHEN** 用户在 Finder 或登录项中启动应用并等待前端就绪
- **THEN** 主窗口始终不出现，菜单栏出现图标，进程在后台待命，按快捷键即可唤出

#### Scenario: 首次启动仍可发现
- **WHEN** 全新安装后首次启动且主窗口保持隐藏
- **THEN** 用户能从菜单栏看到应用并唤出窗口，或收到一次性的快捷键说明，不会误以为应用没启动

### Requirement: 退出确认

通过菜单栏「退出」、`Command+Q` 或系统退出动作请求退出时，系统 MUST 先刷新（flush）所有窗口的未保存编辑——包括主窗口当前笔记与速记面板当前速记——再显示确认对话框。用户取消 MUST 保持应用运行且窗口状态不变；确认后 MUST 结束进程。存在未保存内容或保存失败时 MUST 在对话框中说明，保存失败 MUST NOT 静默退出。速记面板 MUST NOT 自行弹出退出确认框，MUST 只响应主窗口发起的刷新请求。

#### Scenario: 取消退出
- **WHEN** 用户触发退出并在确认对话框中取消
- **THEN** 进程继续运行，窗口显隐状态与编辑内容保持原状

#### Scenario: 确认退出
- **WHEN** 用户触发退出并确认
- **THEN** 主窗口与速记面板的未保存编辑都已落盘，随后进程结束，菜单栏图标消失

#### Scenario: 未保存内容提示
- **WHEN** 存在未保存编辑时触发退出
- **THEN** 确认对话框说明仍有未保存内容；若保存失败则停留在对话框并提示错误，不结束进程

#### Scenario: 退出时只弹一次对话框
- **WHEN** 速记面板可见且用户按 `Command+Q`
- **THEN** 只出现一个退出确认对话框，两个窗口都不会重复请求退出

### Requirement: 全局快捷键唤出

系统 MUST 注册默认全局快捷键 `CommandOrControl+Shift+D` 用于切换主窗口显隐；注册失败 MUST NOT 阻断启动，MUST 以可见提示告知快捷键不可用。快捷键 MUST 可在设置中修改，且 MUST 拒绝已被系统占用的组合。

#### Scenario: 隐藏时唤出
- **WHEN** 窗口处于隐藏状态且用户按下快捷键
- **THEN** 窗口显示、居中、置于最前并获得键盘焦点

#### Scenario: 可见时隐藏
- **WHEN** 窗口可见且用户按下快捷键
- **THEN** 窗口隐藏，应用进程继续运行

#### Scenario: 快捷键冲突
- **WHEN** 用户设置的组合已被其他应用占用
- **THEN** 设置界面提示冲突并要求重新输入，旧快捷键保持有效

### Requirement: 显示时定位与置顶

主窗口每次显示 MUST 恢复上次的窗口尺寸，该尺寸 MUST 跨进程重启持久化（保存到应用配置），MUST 按当前鼠标所在显示器居中并限制在可见区域内，MUST 在显示期间保持置顶，MUST 在隐藏时取消置顶。MUST NOT 保存或恢复主窗口坐标。

持久化的尺寸 MUST 在使用前做合法性收敛：小于最小尺寸（760×480）的值 MUST 提升到最小尺寸，超出当前显示器可见区域的值 MUST 收进可见区域，不得让窗口出现在屏幕外或不可缩放。

配置不可用（文件缺失、内容损坏、写入失败）时 MUST 回退到默认尺寸（1100×720）并继续工作，MUST NOT 阻断启动、显示或隐藏。速记面板的定位与尺寸规则由 `quick-tabs` capability 定义，MUST NOT 套用本条的中心定位规则。

当其他应用正处于全屏（独立 Space）时唤出主窗口，主窗口 MUST 显示在该全屏应用之上，MUST NOT 留在用户原来的桌面或别的 Space，MUST NOT 让用户被动退出全屏。为此主窗口 MUST 是一个全屏辅助面板：窗口类 MUST 为 `NSPanel` 的子类，样式 MUST 含 `NSWindowStyleMaskNonactivatingPanel`，`collectionBehavior` MUST 含 `CanJoinAllSpaces | FullScreenAuxiliary`。仅给普通 `NSWindow` 设置 `collectionBehavior` MUST NOT 被视为满足本条。

该能力 MUST NOT 让主窗口退化为不接收键盘输入的浮层：窗口 MUST 能成为 key，且在成为 key 时 MUST 让本应用成为活动应用（菜单栏归属本应用），原生标题栏、红绿灯、关闭即隐藏（⌘W）与退出确认（⌘Q）语义 MUST 不变。

#### Scenario: 鼠标在副屏
- **WHEN** 鼠标位于副显示器且用户唤出主窗口
- **THEN** 主窗口出现在该显示器中央而非主屏

#### Scenario: 显示器断开
- **WHEN** 上次使用的副屏被拔掉后再唤出主窗口
- **THEN** 主窗口出现在现存显示器可见范围内，不落在屏幕外

#### Scenario: 置顶仅在显示时生效
- **WHEN** 主窗口隐藏后用户切换到其他应用
- **THEN** 其他应用窗口正常获得焦点，不被隐藏窗口抢占

#### Scenario: 调整尺寸后重启仍是上次的尺寸
- **WHEN** 用户把主窗口拖到 1320×860，然后隐藏窗口并退出应用，再重新启动并唤出主窗口
- **THEN** 主窗口以 1320×860 显示，而不是默认的 1100×720

#### Scenario: 保存的尺寸比当前屏幕更大
- **WHEN** 用户在 2560 宽的显示器上把主窗口拉到 2000 宽后退出，随后在 1440 宽的显示器上启动并唤出主窗口
- **THEN** 主窗口被收进 1440 宽显示器的可见区域，四个边都在屏幕内

#### Scenario: 尺寸配置损坏不阻断启动
- **WHEN** 配置文件里的尺寸字段被改成非法内容或整个配置文件损坏
- **THEN** 应用以默认尺寸正常启动与显示，笔记数据不受影响

#### Scenario: 全屏应用之上显示主窗口
- **WHEN** 用户把某个应用切到全屏，然后在菜单栏选择「显示主窗口」
- **THEN** 主窗口显示在该全屏应用之上并可直接输入，那个应用的全屏状态保持不变，用户不必先退出全屏或切 Space

#### Scenario: 焦点跟随菜单栏
- **WHEN** 其他应用在前台，用户点击角落里仍可见的主窗口
- **THEN** 主窗口获得键盘焦点，菜单栏切换为本应用的菜单

### Requirement: 菜单栏常驻

应用 MUST 提供菜单栏图标与菜单。图标左键 MUST 显示或隐藏速记面板，图标右键 MUST 打开应用菜单，两者 MUST 互不干扰（左键不弹菜单、右键不切面板）。菜单 MUST 至少包含：显示主窗口、新建笔记、导入 Markdown…、设置、开机启动开关、退出。菜单项 MUST 与界面内同名操作使用同一业务路径。

菜单 MUST NOT 出现与其他菜单项行为重复的入口。库的查看、路径切换与库信息 MUST 只经「设置」内的库分区提供，MUST NOT 单列一个只做同样事情的菜单项。

#### Scenario: 左键切换速记面板
- **WHEN** 用户点击菜单栏图标左键
- **THEN** 速记面板显示或隐藏，主窗口显隐状态不变

#### Scenario: 右键打开菜单
- **WHEN** 用户点击菜单栏图标右键
- **THEN** 应用菜单展开，速记面板不被切换

#### Scenario: 菜单显示主窗口
- **WHEN** 用户在菜单栏选择「显示主窗口」
- **THEN** 主窗口显示并获得焦点，速记面板保持原状态

#### Scenario: 菜单新建笔记
- **WHEN** 用户在菜单栏选择「新建笔记」
- **THEN** 主窗口显示并进入新建笔记的编辑状态，聚焦标题

#### Scenario: 菜单不出现重复的库入口
- **WHEN** 用户右键打开应用菜单
- **THEN** 菜单中没有「笔记库」一项，库的查看与切换只能经「设置」进入

#### Scenario: 菜单栏显示品牌标识
- **WHEN** 应用运行于菜单栏
- **THEN** 显示品牌 logo（蓝色圆角方块标记），高度约 18pt、按等比缩放，在深浅色菜单栏下都能辨认

### Requirement: 单实例

应用 MUST 保证仅有一个进程实例；重复启动 MUST 唤出已运行实例的主窗口而 MUST NOT 新开进程。

#### Scenario: 重复打开应用
- **WHEN** 应用已在运行（窗口隐藏）时用户从 Finder 再次打开
- **THEN** 已运行实例的窗口显示并聚焦，不出现第二个进程

### Requirement: 开机启动

设置 MUST 提供可开关的登录时启动项，且 MUST 反映系统实际授权状态。

#### Scenario: 开启后状态持久
- **WHEN** 用户开启开机启动并重启系统
- **THEN** 应用在登录后自动运行于菜单栏，主窗口默认隐藏

### Requirement: 编辑区宽度可控

左栏宽度 MUST 可通过拖拽调整，范围 MUST 限制在 220–420px 且不超过窗口宽度的合理比例；宽度 MUST 在下次启动时恢复。

#### Scenario: 拖拽调宽并记住
- **WHEN** 用户把左栏拖到 380px 后重启应用
- **THEN** 左栏宽度仍为 380px

#### Scenario: 窄窗口下不挤压内容区
- **WHEN** 窗口缩小到最小尺寸且左栏为 420px
- **THEN** 左栏被限制到合法上限，右侧内容区仍可使用

### Requirement: 主窗口无标题栏

主窗口 MUST NOT 显示系统标题栏：窗口标题文字 MUST 隐藏，标题栏底色 MUST 透明，内容 MUST 顶到窗口最上沿。窗口 MUST 保留原生窗口控制按钮（红/黄/绿）、系统圆角与阴影、双击缩放，以及关闭即隐藏、退出确认的既有语义；MUST NOT 改成无边框窗口或自绘标题栏。

窗口顶部 MUST 提供拖拽区，使窗口仍可被拖动。拖拽区 MUST 横跨窗口宽度，其左段宽度 MUST 与侧栏宽度一致、底色与侧栏一致并延续侧栏分隔线，右段底色与正文一致。内容 MUST NOT 被红绿灯遮挡。

拖拽 MUST 在窗口未处于前台时也生效：其他应用在前台时唤出主窗口，第一次按住拖拽区即可移动窗口，MUST NOT 要求先点一次把窗口激活。

#### Scenario: 主窗口没有标题栏
- **WHEN** 用户通过快捷键唤出主窗口
- **THEN** 窗口顶部没有标题文字与标题栏底色，侧栏与正文从窗口上沿开始，红绿灯浮在左上且不遮挡任何文字或控件

#### Scenario: 顶部拖拽
- **WHEN** 用户按住主窗口顶部那条空条拖动
- **THEN** 整个窗口跟随移动，位置仍按"显示时按鼠标所在显示器居中"的规则在下次唤出时重置

#### Scenario: 窗口未激活时的第一次拖拽
- **WHEN** 其他应用在前台时唤出主窗口，用户不做任何点击，直接按住顶部拖拽区拖动
- **THEN** 窗口立即跟随移动并同时成为前台应用，不需要先点一次再拖

#### Scenario: 窗口控制按钮仍可用
- **WHEN** 用户点击左上角红色按钮
- **THEN** 窗口隐藏而不退出进程；点击绿色按钮进入全屏、黄色按钮最小化，与改造前一致
