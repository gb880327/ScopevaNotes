## Purpose

定义速记（Quick Tab）这一独立于笔记的第二实体：从菜单栏一次呼出的纯文本临时记录面板，多 Tab 切换、自动保存、数量受限，与笔记体系完全隔离且没有进入笔记体系的通道。

## ADDED Requirements

### Requirement: 速记数据模型

系统 MUST 在独立表 `quick_tabs` 中存储速记，字段 MUST 为：稳定 id、标题、颜色键、纯文本正文、排序序号、创建时间、更新时间。id MUST 为 UUIDv7，时间戳 MUST 为 Unix 毫秒（UTC），颜色 MUST 只存固定颜色键（不得存 CSS 值或类名）。速记 MUST NOT 写入 `notes`、`note_tags`、`tags` 或 `notes_fts`，正文 MUST 原样保留换行、制表符、Unicode 与 emoji，MUST NOT 做任何 Markdown 解释或改写。

#### Scenario: 创建速记只写一张表
- **WHEN** 用户点击 `+` 新建一个速记
- **THEN** `quick_tabs` 新增一行，`notes` 与 `notes_fts` 行数不变

#### Scenario: 正文原样保存
- **WHEN** 用户在一个速记里输入包含换行、制表符、中文、emoji 与 CRLF 的多行文本并等待自动保存完成
- **THEN** 重新读取到的正文与输入逐字节一致

### Requirement: 速记与笔记体系隔离

速记 MUST NOT 出现在笔记列表、搜索结果、标签计数、回收站或导入批次中；系统 MUST NOT 提供任何把速记转换为笔记的命令或界面入口；删除速记 MUST 是永久删除，MUST NOT 进入回收站，MUST NOT 提供撤销。用户如需留存内容 MUST 通过原生复制粘贴自行搬运。

#### Scenario: 搜索找不到速记内容
- **WHEN** 某速记正文含唯一字符串，用户在主窗口搜索该字符串
- **THEN** 搜索结果为空，且数据库 `notes_fts` 中不存在包含该字符串的行

#### Scenario: 回收站不含速记
- **WHEN** 用户永久删除一个速记后打开回收站
- **THEN** 回收站列表与条数均不因该速记发生变化

#### Scenario: 界面上没有转换出口
- **WHEN** 用户打开速记的「更多」菜单
- **THEN** 菜单只包含重命名、换色、复制、删除，不存在「转换为笔记」一类的入口

### Requirement: 速记数量上限

速记数量 MUST 固定上限为 12 个。达到上限后新建请求 MUST 被服务端拒绝（不得只依赖界面禁用），MUST 返回可读错误而不是数据库错误，MUST NOT 留下任何半成品记录；界面 MUST 禁用 `+` 并显示「速记最多 12 个」。删除任一个速记后 MUST 可以再次新建。

#### Scenario: 第 13 个被拒绝
- **WHEN** 已存在 12 个速记时再次请求新建
- **THEN** 返回校验类错误，速记总数仍为 12，界面显示上限提示

#### Scenario: 腾出位置后可以新建
- **WHEN** 用户删除一个速记后再新建
- **THEN** 新建成功，总数回到 12

### Requirement: 速记面板的显示与隐藏

速记 MUST 在独立窗口（label `quick-tabs`）中呈现，该窗口 MUST 无标题栏、置顶显示、在所有 Space 可见（**包括其他应用的全屏 Space**）、且在应用启动时创建但隐藏。菜单栏图标左键 MUST 切换其显隐；面板可见时 MUST 接受 `Esc` 隐藏；面板失焦时 MUST 自动隐藏；点击窗口关闭按钮 MUST 只隐藏面板而 MUST NOT 结束进程也 MUST NOT 隐藏主窗口。面板显示后 MUST 让当前速记的编辑区获得焦点。

#### Scenario: 失焦自动隐藏
- **WHEN** 面板可见且用户点击其他应用的窗口
- **THEN** 面板隐藏，进程与主窗口状态不变

#### Scenario: Esc 隐藏
- **WHEN** 面板可见且编辑区有焦点，用户按下 `Esc`
- **THEN** 面板隐藏，再次唤出时仍停在原来的速记

#### Scenario: 因失焦隐藏的瞬间不重新打开
- **WHEN** 面板可见且用户点击菜单栏图标想关掉它
- **THEN** 面板最终处于隐藏状态（不因失焦隐藏与左键切换的先后顺序而闪回）

#### Scenario: 关闭按钮不退出也不误伤主窗口
- **WHEN** 面板可见时用户点击其关闭按钮
- **THEN** 面板隐藏，进程继续运行，主窗口显隐状态不变

#### Scenario: 全屏应用之上也能呼出
- **WHEN** 前台应用正处于全屏 Space，用户点击菜单栏图标左键
- **THEN** 面板出现在该全屏 Space 之上并接受输入，不切换到其他桌面或显示器，主窗口显隐状态不变

### Requirement: 速记面板的定位

面板显示时 MUST 以菜单栏图标的位置为锚点定位（图标下方、水平居中对齐图标）并 MUST 限制在图标所在显示器的可见区域内，MUST 处理多显示器与不同缩放比例。MUST NOT 保存或恢复面板坐标；面板尺寸 MUST 在下次显示时恢复，且有最小尺寸限制。当菜单栏处于自动隐藏状态（即当前处于全屏 Space）时，面板 MUST 改为贴住所在显示器顶边，MUST NOT 在滑走的菜单栏位置留下空隙。

#### Scenario: 副屏图标在副屏弹出
- **WHEN** 菜单栏图标位于副显示器且用户点击它
- **THEN** 面板出现在该显示器上、贴着菜单栏而不越出屏幕

#### Scenario: 显示器断开后仍在可见区域
- **WHEN** 上次显示面板的显示器被拔掉后再唤出面板
- **THEN** 面板出现在现存显示器的可见区域内

### Requirement: 速记 Tab 的增删改复制

系统 MUST 支持速记的创建、切换、重命名、改色、复制与删除。切换 MUST 只改变当前选中的速记并保存上一个速记的待存内容。重命名 MUST 保留正文、颜色与时间戳语义。复制 MUST 生成一个内容独立的新速记，不共享正文。删除 MUST 每次都要求确认，确认文案 MUST 说明不可恢复；取消 MUST NOT 删除任何数据。固定颜色键至少包含黄、橙、红、紫、蓝、青、绿七种。

#### Scenario: 切换前先保存
- **WHEN** 用户在速记 A 输入文字后立即切到速记 B
- **THEN** A 的新内容已经落盘，切回 A 时看到的是刚输入的内容

#### Scenario: 删除需要确认
- **WHEN** 用户对某个速记触发删除，并在确认中选择取消
- **THEN** 该速记仍在列表中且内容不变

#### Scenario: 复制得到独立副本
- **WHEN** 用户复制一个速记后修改副本
- **THEN** 原速记内容不受影响

### Requirement: 速记标签栏的布局与视觉

标签栏 MUST 是单行固定高度 56px 的容器，内部左右两组 MUST 两端对齐（`justify-content: space-between`）且所有子元素垂直居中。左侧为圆点组，组内间距 MUST 为 10px，超出可用宽度时 MUST 横向滚动而 MUST NOT 换行撑高标签栏。每个圆点的点击区域 MUST 为 36×36；当前选中的圆点 MUST 增大到 40×40；新建按钮 MUST 为 40×40；「更多」按钮高度 MUST 为 40px。标签栏 MUST 沿用主题背景色并带一条浅分隔线；可点击元素 MUST 有 hover 反馈，选中态 MUST 同时靠尺寸与描边表达（不可只靠颜色）。圆角 MUST 统一使用设计令牌。

#### Scenario: 标签栏密度与选中放大
- **WHEN** 面板中有 12 条速记并选中其中一条
- **THEN** 标签栏仍是 56px 单行、圆点组横向滚动不换行，选中圆点比其余圆点更大且带描边，新建按钮与「更多」按钮垂直居中

### Requirement: 自动保存与草稿恢复

编辑 MUST 以约 300 ms 防抖写库；切换速记、面板隐藏、失焦、退出应用前 MUST flush 待存内容。保存失败 MUST 保留用户输入与草稿、MUST 显示可见的失败状态并 MUST 允许重试，MUST NOT 清空编辑区。每次防抖重置时 MUST 将草稿快照写入应用本地存储，使崩溃或强制退出后可恢复；成功写库后 MUST 清除对应快照；面板重新挂载时若快照比库中记录更新，MUST 用它恢复并标记为未保存。

#### Scenario: 保存失败保留输入
- **WHEN** 写库失败（例如库被其他进程占用）
- **THEN** 编辑区内容不变，状态栏显示保存失败，重试成功后状态回到已保存

#### Scenario: 崩溃后恢复草稿
- **WHEN** 用户输入后进程被强制结束，随后重新打开面板
- **THEN** 该速记的编辑区显示未落盘的草稿内容并处于未保存状态

#### Scenario: 成功保存后不留快照
- **WHEN** 一次自动保存成功完成
- **THEN** 该速记的本地草稿快照被清除

### Requirement: 主题、可访问性与输入法

面板 MUST 沿用全局浅色、深色与跟随系统主题，文字对实际渲染背景的对比度 MUST 达到 4.5:1。圆点的选中态 MUST NOT 只依靠颜色区分，MUST 提供额外的视觉标记（描边、外圈或亮度）且 MUST NOT 低于对比度要求。每个圆点 MUST 有可访问名称，包含颜色与速记标题。编辑区 MUST 保留原生文本编辑快捷键与方向键行为，输入法组合输入期间 MUST NOT 触发隐藏或切换。

#### Scenario: 选中态不只靠颜色
- **WHEN** 用户同时看到未选中与选中的圆点
- **THEN** 两者在灰阶或色盲模拟下仍可区分

#### Scenario: 输入法组合不被打断
- **WHEN** 用户在编辑区用中文输入法连续输入并仍在组合中
- **THEN** 面板保持可见，组合未提交时不会触发保存以外的界面动作
