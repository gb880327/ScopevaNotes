## Context

See `proposal.md` — Why. 现状约束：

- 后端已有 `tag_repo::{create, rename, delete}`，`delete` 会在同一事务里删 `tags` 行（`note_tags` 靠 `ON DELETE CASCADE`）、然后对每条受影响笔记调 `search_index::reindex_note`。
- `note_repo::update` 已接受 `tagIds: Option<Vec<String>>` 并在同事务里 `replace_tags` + `reindex_note`，前端 `commands.ts` 也有 `updateNote`。
- 产品契约（`macos-shell` / `notes-core`）：单主窗口、无第三栏、无多窗口。设置是一个含多 section 的模态（外观 / 快捷键 / 启动 / 库 / 迁移）。
- `tags.color` 列早已存在，`list_with_counts` 已返回 `noteCount`。

## Goals / Non-Goals

**Goals:**

- 标签的四个动作（新增 / 重命名 / 改色 / 删除）都能在界面上完成，且都能看到后果（计数、受影响笔记数）。
- 笔记上的标签从"只读文本"变成可编辑 chip，走既有写路径而不是第二套写入逻辑。
- 失败可见：冲突、空名、孤儿标签都必须在界面上呈现，不静默。

**Non-Goals:**

- 不做标签层级 / 嵌套树（`a/b` 仍只是一等名称字符串，不解析成父子关系）。
- 不做标签合并（重命名到已存在名称即报冲突，不提供"合并两个标签"的语义）。
- 不做多选笔记批量打标签。
- 不新增 `tags` 表列或迁移。

## Decisions

**D1 管理入口放设置模态的新「标签」section，不做第三栏或独立窗口。**
理由：v1 明确禁止第三栏/多窗口；设置已经是"一次性配置"的容器，标签维护正是低频操作。备选（侧栏就地编辑每个标签）被否：侧栏一行只有 ~200px，放名称 + 计数 + 三个按钮会挤掉笔记列表，且误触删除的风险高。

**D2 笔记标签编辑内联在笔记头部，写路径复用 `update_note` 的 `tagIds`。**
理由：`update` 已保证"改标签 → 重建索引 → 冲突检测"在同一事务里，另开 `add_note_tag` / `remove_note_tag` 会造成第二套写路径与第二套索引维护点（`design` D9 的同类错误）。代价是每次 chip 操作都发一次完整 `update_note`（含 title/content），在自动保存队列里排队——与"改标题"的代价相同，可接受。

**D3 删除确认用应用内内联确认，不用原生对话框。**
理由：原生 `confirm` 需要在 Rust 侧阻塞等待（`begin_quit_prompt` 那套），而导入的「删除本批」已经证明内联确认够用且可测。确认文案必须含受影响笔记数（来自 `list_with_counts`，不需要新查询）。

**D4 改色用固定调色板（复用现有令牌里的强调色集合），不引入颜色选择器依赖。**
理由：`tags.color` 是自由字符串，但 UI 只提供 8 个可选值即可满足"区分标签"的用途；引入 `color picker` 组件会把一个依赖带进打包体积。

**D5 "输入新名称即建即挂" = 先 `create_tag` 再 `update_note`，不合并成一条命令。**
理由：合并需要在 `update_note` 里接受名称并做 upsert，会改动已冻结的 DTO 与并发语义。两步的失败模式（标签建好但没挂上）必须**可见**：提示"标签已创建，但挂到笔记失败"，且该标签会出现在管理界面里——用户可再挂一次，而不是留下一个看不见的孤儿。

**D6 标签计数与列表在同一次刷新里更新，不做乐观本地加减。**
理由：计数由 `list_with_counts` 单查询给出（`标签列表带计数` 要求"不得为每个标签单独查询"），乐观加减一旦与服务端不一致就会长期偏差；标签操作是低频动作，直接重取 `list_tags` 更省心。

## Risks / Trade-offs

- **删除被大量笔记使用的标签是 O(N²)**：`delete` 对每条受影响笔记调 `reindex_note`，而 `notes_fts.note_id` 是 UNINDEXED，「先删后插」每删一次都全表扫描（见 `mem:search` 与 import D14）。1,000 条笔记共用同一标签时删除会退化成秒级。→ 确认文案给出受影响笔记数，任务里加一条基准（1,000 条关联）并把实测数字写进 `verification.md`；若实测超过 1 s，再考虑改成"清空+全量重建"。
- **两步创建留下孤儿标签**：见 D5，靠可见提示 + 管理界面兜底。
- **设置模态变杂物间**：section 从 5 个涨到 6 个。→ 入口排序把「标签」放在「库」之后，不与日常操作竞争。
- **chip 行与标题行争宽度**：标签多时头部会换行挤压标题。→ 标签区独立一行、超出时横向滚动（不换行），与既有 `.meta` 行一致。
