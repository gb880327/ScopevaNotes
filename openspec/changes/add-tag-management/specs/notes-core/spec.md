## ADDED Requirements

### Requirement: 标签管理界面

系统 MUST 提供一个集中的标签管理入口，列出全部标签及其颜色与可见笔记数，并 MUST 支持新增、重命名、改色与删除。新增与重命名 MUST 沿用既有的归一化与大小写不敏感唯一规则：重名 MUST 返回可见冲突错误而不是静默合并。删除 MUST 先显示将被摘除关联的可见笔记数并要求确认；删除 MUST NOT 删除任何笔记，也 MUST NOT 影响这些笔记的正文与时间戳。任一操作失败后 MUST NOT 留下部分更新（标签未改、关联未动、列表与计数保持原状）。

#### Scenario: 重命名标签同步界面与搜索
- **WHEN** 用户在管理界面把标签 `db` 重命名为 `database`
- **THEN** 标签列表、笔记上的标签 chip 与按 `database` 的搜索结果同时反映新名称，且原名称不再出现在标签列表中

#### Scenario: 删除标签先确认再摘除
- **WHEN** 用户删除一个被 3 条可见笔记使用的标签
- **THEN** 系统先提示将影响 3 条笔记，确认后这 3 条笔记仍存在、正文与时间戳不变、仅失去该标签，标签计数与过滤结果立即更新

#### Scenario: 重名被拒绝并保留原状态
- **WHEN** 已存在 `Rust` 时用户在管理界面把 `db` 重命名为 `rust`
- **THEN** 系统显示冲突错误，`db` 与原有关联保持不变，列表不出现 `rust`

#### Scenario: 空名称不创建标签
- **WHEN** 用户提交只含空白字符的标签名
- **THEN** 系统不创建标签，也不显示新的标签行

### Requirement: 笔记标签编辑

笔记头部 MUST 展示该笔记当前标签，并 MUST 允许用户为当前笔记添加已有标签、输入新名称新建并立即挂上该笔记、以及摘除某个标签。标签变更 MUST 走与正文相同的保存路径（含乐观并发与自动保存），MUST 在保存成功后立即反映到标签列表计数与搜索结果；保存失败 MUST 显示可见错误并保留用户这次操作的结果（不得静默丢弃，也不得只在下次刷新时消失）。

#### Scenario: 添加已有标签
- **WHEN** 用户在笔记头部选择一个已存在的标签
- **THEN** 该标签出现在笔记标签区，标签列表中该标签的计数加一，按该标签过滤能命中这条笔记

#### Scenario: 输入新名称即建即挂
- **WHEN** 用户在笔记头部输入一个不存在的标签名并确认
- **THEN** 系统新建该标签并立即挂到当前笔记，同时出现在标签管理界面中

#### Scenario: 摘除只影响本笔记
- **WHEN** 用户从一条笔记上摘除标签 `work`，而 `work` 仍被其它笔记使用
- **THEN** 仅这条笔记失去该标签，其它笔记的关联与标签本身都保留

#### Scenario: 保存失败时可见且不丢输入
- **WHEN** 标签变更因版本冲突或数据库错误保存失败
- **THEN** 界面显示可读错误，用户刚添加或摘除的标签状态保留在界面上，不会静默回滚
