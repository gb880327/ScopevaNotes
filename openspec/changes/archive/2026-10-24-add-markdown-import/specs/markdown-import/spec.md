## Purpose

让从其他应用（目前是 Obsidian）迁移过来的用户，把一个目录里的 Markdown 文件一次性变成笔记库里的笔记：发现、解码、提取标题与标签、保留原始时间顺序，并给出一份可核对、可撤销的导入报告。本能力是一次性迁移通道，不是同步机制。

## ADDED Requirements

### Requirement: 导入入口与三阶段流程

应用 MUST 提供「导入 Markdown」入口（菜单栏菜单项与设置面板各一处），点击后打开一个覆盖在笔记列表上的模态，模态 MUST 依次呈现三个阶段：选目录与预览统计、导入中进度、结果报告。导入进行中 MUST NOT 允许关闭模态；导入结束后 MUST 可以关闭并回到笔记列表。

#### Scenario: 从菜单栏进入导入
- **WHEN** 用户点击菜单栏菜单中的「导入 Markdown…」
- **THEN** 主窗口被唤出并显示导入模态的第一阶段，光标不在任何破坏性按钮上

#### Scenario: 导入中不可关闭
- **WHEN** 导入正在进行且用户尝试关闭模态
- **THEN** 模态保持打开并提示需要先等待完成或点击取消

#### Scenario: 完成后可返回
- **WHEN** 导入完成并展示报告
- **THEN** 用户关闭模态后，笔记列表反映导入结果（新笔记按导入时间戳排在其应在的位置）

### Requirement: 目录发现与跳过规则

导入 MUST 递归收集所选目录下的 `.md` 与 `.markdown` 文件，且 MUST 跳过：隐藏目录与隐藏文件（含 `.obsidian/`、`.trash/`）、`node_modules/`、符号链接目录。MUST NOT 收集其他扩展名的文件。跳过的隐藏条目数量 MUST 在预览阶段可见，而不是静默忽略。

#### Scenario: 跳过 Obsidian 配置目录
- **WHEN** 用户选择一个包含 `.obsidian/` 与 `.trash/` 的 Obsidian vault
- **THEN** 预览统计中不包含这两个目录下的任何文件，且显示被跳过的隐藏条目数量

#### Scenario: 只收 Markdown
- **WHEN** 目录中同时存在 `.md`、`.markdown`、`.png`、`.pdf` 与 `.txt`
- **THEN** 只有 `.md` 与 `.markdown` 被计入待导入数量

#### Scenario: 符号链接不跟随
- **WHEN** 目录中存在指向父目录的符号链接
- **THEN** 发现过程正常结束且不重复收集文件

### Requirement: 预览统计（dry-run）

执行导入 MUST 之前先给出一份预览：待导入条数、已导入将跳过的条数、被跳过的隐藏条目数、以及正文中引用本地文件（图片等）的笔记条数。用户 MUST 能在看到这份预览后选择继续或放弃，放弃 MUST NOT 写入任何数据。

#### Scenario: 预览不写库
- **WHEN** 用户完成目录选择后关闭模态而没有点击导入
- **THEN** 笔记库中的笔记数量、标签数量与搜索索引均未改变

#### Scenario: 预览显示将跳过的已导入项
- **WHEN** 上一次导入已把该目录中的 300 条笔记写入，用户再次选择同一目录
- **THEN** 预览显示「将导入 0 条、跳过 300 条（已导入）」

### Requirement: 解码与文件级失败隔离

导入 MUST 以 UTF-8 解码文件（允许并去除 BOM）。当字节不是合法 UTF-8 时 MUST 尝试 GB18030 解码，成功后该笔记 MUST 在报告中被标注为「按 GB18030 解码」；仍然失败的文件 MUST 计为失败并附原因，且 MUST NOT 写入任何部分内容。

#### Scenario: UTF-8 BOM
- **WHEN** 文件以 UTF-8 BOM 开头
- **THEN** 导入后的笔记标题与正文都不包含 BOM 字符

#### Scenario: GB18030 回退
- **WHEN** 文件是合法的 GB18030 而不是合法的 UTF-8
- **THEN** 笔记内容正确（无乱码），且报告把该文件列为「按 GB18030 解码」

#### Scenario: 无法解码
- **WHEN** 文件既不是合法 UTF-8 也不是合法 GB18030
- **THEN** 该文件出现在失败清单并带原因，笔记库中不新增该笔记

### Requirement: frontmatter 与标题、标签提取

导入 MUST 剥离笔记开头的 YAML frontmatter，但 MUST NOT 改变正文其余部分的字节。标题 MUST 按以下顺序取值：frontmatter 中的 `title`，首个以单个 `#` 开头的标题行，去掉扩展名的文件名；取到标题后 MUST NOT 从正文中删除该标题行。标签 MUST 从 frontmatter 的 `tags` 提取（支持 YAML 列表与逗号分隔字符串，允许 `#` 前缀，允许 `a/b` 形式的嵌套名），同名标签 MUST 复用而不是重复创建。frontmatter 的 `created`（ISO 日期或时间戳）MUST 用作该笔记的创建时间。

#### Scenario: 剥掉 frontmatter，正文不变
- **WHEN** 文件开头是 `---\ntitle: 项目笔记\ntags: [work, 2026]\n---` 后接正文
- **THEN** 笔记正文从 `---` 之后的第一行开始，预览中不出现 YAML 内容

#### Scenario: 标题优先级
- **WHEN** 文件没有 frontmatter 但有 `# 手写标题`，且文件名为 `未命名 3.md`
- **THEN** 笔记标题是「手写标题」，且正文中仍包含这一行

#### Scenario: 复用同名标签
- **WHEN** 库中已存在标签 `work`，导入的 20 个文件 frontmatter 都写了 `tags: work`
- **THEN** 标签表中仍只有一条 `work`，20 条笔记都关联到它

#### Scenario: 嵌套标签
- **WHEN** frontmatter 写着 `tags: [项目/子项目]`
- **THEN** 笔记关联的标签名是 `项目/子项目`

#### Scenario: 可选的目录名标签
- **WHEN** 用户在导入选项中开启了「用父目录名作为标签」
- **THEN** 位于 `Projects/` 下的笔记额外获得标签 `Projects`，未开启时不会

### Requirement: 时间戳保留原始顺序

导入的笔记 MUST 以文件 `mtime` 作为 `updated_at`；当系统提供文件创建时间时 MUST 以它作为 `created_at`，否则回退到 `mtime`；两者都取不到时才使用当前时间。导入 MUST NOT 把所有导入笔记的时间戳都写成导入时刻。

#### Scenario: 旧笔记不挤占列表顶部
- **WHEN** 用户导入 300 个最后修改于两年前的文件
- **THEN** 这些笔记在按更新时间排序的列表中出现于原有笔记之下，且相互之间保持原有先后顺序

### Requirement: 正文保真与未迁移内容的可见说明

导入 MUST NOT 改写正文中的链接、图片引用或 Obsidian 扩展语法（`[[双链]]`、`![[嵌入]]`、`==高亮==`、`%%注释%%`、`> [!note]` callout、`^块引用` 均原样保留）。报告 MUST 显式给出「正文引用了本地文件但本版不迁移」的笔记条数，并说明这些文件需要用户自行保留。MUST NOT 静默丢弃或静默改写这些引用。

#### Scenario: 图片引用保持原样
- **WHEN** 笔记正文含有 `![](img/a.png)`
- **THEN** 导入后正文仍逐字包含 `![](img/a.png)`，且报告把它计入「引用了本地文件、未迁移」的统计

#### Scenario: 双链不被改写
- **WHEN** 笔记正文含有 `[[另一条笔记|别名]]`
- **THEN** 导入后的正文与原文逐字一致

#### Scenario: 只读原目录
- **WHEN** 导入任意目录
- **THEN** 原目录中没有任何文件被创建、修改或删除（时间戳也不变）

### Requirement: 幂等重试

笔记 MUST 记录导入来源的绝对路径。当同一路径的笔记已存在时，导入 MUST 跳过该文件而不是再插入一条，因此对同一目录重复执行导入 MUST NOT 产生重复笔记；已经导入的条数 MUST 在预览与报告中分别计数。

#### Scenario: 重跑同一目录
- **WHEN** 用户连续两次导入同一个包含 300 条笔记的目录
- **THEN** 第一次导入 300 条，第二次导入 0 条并跳过 300 条，笔记总数仍为 300

#### Scenario: 中途失败后重试
- **WHEN** 一次导入在 180/300 处因磁盘错误中断，用户修复后重新导入同一目录
- **THEN** 已成功的 180 条被跳过，只补齐剩余的 120 条

#### Scenario: 手工新建的笔记不受影响
- **WHEN** 库中存在 50 条手工新建的笔记（没有来源路径）
- **THEN** 导入不会把它们计入「已跳过」也不会修改它们

### Requirement: 批量提交、进度与取消

导入 MUST 分批提交（每批不超过 500 条），并在进行中通过事件上报已完成条数与总数。用户 MUST 能取消；取消后已提交的批次 MUST 保留并计入报告，未处理的文件 MUST 不再写入。导入期间应用 MUST 保持可响应，且对同一笔记库的其他写入（例如正在编辑的笔记自动保存）MUST NOT 静默失败 —— 若因此发生锁冲突，用户 MUST 看到可见的错误而不是丢失编辑。

#### Scenario: 大批量导入可取消
- **WHEN** 导入 5,000 个文件时用户点击取消
- **THEN** 导入在有限时间内停止，报告显示已导入的条数与「已取消」，应用可继续使用

#### Scenario: 进度可见
- **WHEN** 导入进行中
- **THEN** 模态显示形如「已导入 1,200 / 5,000」的进度

#### Scenario: 锁冲突不静默
- **WHEN** 导入占用写入连接期间，编辑器对已打开笔记的自动保存失败
- **THEN** 用户看到可见的错误提示，且该笔记保持未保存状态以便重试

### Requirement: 导入报告

导入结束后 MUST 展示一份报告，包含：成功条数、跳过条数（已导入）、失败条数及逐文件失败原因、跳过的隐藏条目数、按 GB18030 解码的条数、引用了本地文件而未迁移的条数、耗时。报告 MUST 能区分「失败」与「跳过」。当存在失败时，报告 MUST 提供逐条清单而不是仅给出总数。

#### Scenario: 部分失败
- **WHEN** 300 个文件中有 2 个无法解码
- **THEN** 报告显示「成功 298、失败 2」，并列出这 2 个文件的路径与原因

#### Scenario: 没有失败时不显示失败清单
- **WHEN** 全部文件导入成功
- **THEN** 报告不出现空的失败清单区域

### Requirement: 整批撤销

每次导入 MUST 给本批全部笔记打上一个可识别的批次标签（含日期），报告 MUST 提供「删除本批」入口；执行后这些笔记 MUST 进入回收站而不是被永久删除，用户 MUST 能从回收站恢复。

#### Scenario: 撤销后进入回收站
- **WHEN** 用户在一次导入的报告里点击「删除本批」
- **THEN** 该批笔记从列表消失并出现在回收站中，可从回收站恢复

#### Scenario: 撤销只影响本批
- **WHEN** 用户撤销本次导入
- **THEN** 早前导入或手工新建的笔记不受影响

### Requirement: 导入后的可用性

导入完成后 MUST 满足：新笔记可搜索（全文索引在提交时同步更新）、可编辑、可加标签、可删除；既有笔记的内容、标签、收藏与时间戳 MUST 保持不变。

#### Scenario: 导入的笔记可被搜索
- **WHEN** 导入的笔记正文包含「迁移验证关键字」，导入结束后搜索该词
- **THEN** 该笔记出现在搜索结果中

#### Scenario: 既有笔记不变
- **WHEN** 导入前后对既有笔记做快照比较
- **THEN** 标题、正文、标签、收藏状态与时间戳均未改变
