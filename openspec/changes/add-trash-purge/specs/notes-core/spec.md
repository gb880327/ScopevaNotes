## ADDED Requirements

### Requirement: 永久删除

系统 MUST 支持把一条已在回收站的笔记永久删除，以及一次性清空回收站。永久删除 MUST 只由用户显式触发（单条删除或清空），且 MUST 先显示将删除的条数与"不可恢复"提示并要求确认；取消确认 MUST NOT 删除任何数据。永久删除 MUST 在同一事务内移除该笔记的正文、标签关联与搜索索引条目，且 MUST NOT 影响任何未删除笔记。永久删除 MUST NOT 提供撤销。导入批次撤销与普通删除 MUST 仍然只进回收站，任何自动流程 MUST NOT 永久删除。

#### Scenario: 单条永久删除
- **WHEN** 用户在回收站对一条笔记确认永久删除
- **THEN** 该笔记从回收站消失、正文与标签关联被删除、按其中关键词搜索不到，库中不再有这条记录

#### Scenario: 清空垃圾箱
- **WHEN** 用户在回收站确认清空
- **THEN** 回收站中全部笔记被永久删除，回收站显示空态，未删除笔记的数量、内容与时间戳保持不变

#### Scenario: 取消确认不删除
- **WHEN** 用户在永久删除或清空的确认框上选择取消
- **THEN** 回收站内容与笔记总数不变，不发出任何删除请求

#### Scenario: 永久删除后释放导入来源
- **WHEN** 用户永久删除一条由 Markdown 导入产生的笔记，随后再次导入同一目录
- **THEN** 该文件被重新导入为新笔记（软删除状态下则仍被跳过）

### Requirement: 回收站视图

回收站 MUST 以列表形式展示已删除笔记的标题、摘要、标签与删除时间，MUST 显示当前条数，并 MUST 为每条提供恢复与永久删除两个操作，同时 MUST 提供清空垃圾箱入口。已删除笔记 MUST NOT 进入普通列表、搜索与标签计数。回收站为空时 MUST 显示空态而不是空列表。

#### Scenario: 回收站展示删除时间
- **WHEN** 用户打开回收站且其中有 3 条笔记
- **THEN** 列表显示 3 条、条数为 3，每条都显示删除时间，可按删除时间倒序阅读

#### Scenario: 恢复后回到普通列表
- **WHEN** 用户在回收站对一条笔记点击恢复
- **THEN** 该笔记从回收站消失并出现在普通列表与搜索结果中，条数减一

#### Scenario: 空回收站显示空态
- **WHEN** 回收站中没有任何笔记（从未删除或刚刚清空）
- **THEN** 界面显示空态提示，不显示清空按钮为可用状态
