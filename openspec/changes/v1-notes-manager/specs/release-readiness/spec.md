## Purpose

定义可交付的质量基线：资源占用与响应延迟、数据安全演练、打包与签名要求以及必须随版本更新的文档。

## ADDED Requirements

### Requirement: 常驻资源占用

隐藏到菜单栏后，应用 MUST 在 24 小时驻留中保持稳定：空闲 CPU MUST 接近 0，内存 MUST NOT 随驻留时间持续增长。

#### Scenario: 空闲驻留
- **WHEN** 应用隐藏到菜单栏并空闲 24 小时
- **THEN** 进程无持续 CPU 占用，内存曲线无单调增长

### Requirement: 唤出与启动延迟

从触发全局快捷键到窗口可见 MUST 在 200ms 内开始呈现；冷启动到可交互 MUST 在 3s 内完成（10,000 条笔记规模）。

#### Scenario: 热唤出延迟
- **WHEN** 应用已驻留且用户按下全局快捷键
- **THEN** 窗口在 200ms 内可见并可接受键盘输入

### Requirement: 数据安全演练

发布前 MUST 完成并通过：迁移失败回滚、写入过程中强制结束进程后重启、备份文件还原、只读目录打开失败、schema 版本过新拒绝写入。

#### Scenario: 强制结束后恢复
- **WHEN** 保存过程中进程被强制结束，随后重新启动
- **THEN** 数据库可正常打开，最后一次已提交的编辑完整，未提交编辑不产生半写记录

#### Scenario: 备份还原
- **WHEN** 用备份文件替换当前笔记库并启动
- **THEN** 笔记、标签与搜索均可正常工作

### Requirement: 打包与分发

构建 MUST 产出可运行的 `.app`（开发阶段允许仅本地构建）；对外分发 MUST 使用 Developer ID 签名并完成公证，MUST NOT 依赖未签名的调试构建。

#### Scenario: 本地构建可用
- **WHEN** 执行发布构建
- **THEN** 生成的 `.app` 可在未安装开发工具链的机器上启动并读写笔记

#### Scenario: 分发版本通过校验
- **WHEN** 用户从网络下载分发版本首次打开
- **THEN** 系统不出现「无法验证开发者」阻断

### Requirement: 发布文档

每个发布 MUST 附带：安装与首次使用说明、快捷键说明、笔记库位置与备份方法、已知限制。

#### Scenario: 用户能找到数据位置
- **WHEN** 用户阅读发布文档
- **THEN** 文档明确写出默认笔记库路径与备份/迁移步骤
