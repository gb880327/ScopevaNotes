## Purpose

管理笔记库文件本身：默认位置、用户指定路径、schema 版本、完整性以及打开、新建、迁移、备份时的数据安全。

## ADDED Requirements

### Requirement: 默认笔记库位置

首次启动 MUST 在 `Application Support/com.scopeva.notes/notes.db` 创建笔记库；用户 MUST 能通过系统文件选择器指定其他位置，选择结果 MUST 持久化为指针配置，MUST NOT 复制数据后继续写默认库。

#### Scenario: 首次启动建库
- **WHEN** 应用在没有配置的机器上首次启动
- **THEN** 在默认路径创建数据库并完成全部迁移，界面可立即新建笔记

#### Scenario: 切换到自选路径
- **WHEN** 用户在设置中选择一个已有 `.db` 文件
- **THEN** 应用打开该文件并显示其笔记，后续写入目标为新路径

### Requirement: 打开既有笔记库

打开 MUST 校验文件存在、可读、通过完整性检查且 schema 版本不高于程序支持版本；任一校验失败 MUST 返回错误并保留当前笔记库不变，MUST NOT 静默新建空库替换。

#### Scenario: 路径失效
- **WHEN** 配置指向的文件已被移动或删除
- **THEN** 界面显示可读的错误提示与「重新选择 / 使用默认库」入口，不显示空列表冒充成功

#### Scenario: 损坏文件
- **WHEN** 用户选择一个非数据库文件
- **THEN** 打开失败并提示文件无效，当前笔记库仍可用

#### Scenario: 版本过新
- **WHEN** 目标文件 schema 版本高于当前程序支持的版本
- **THEN** 打开被拒绝且文件不被写入

### Requirement: 新建笔记库不覆盖

新建笔记 MUST 在目标文件已存在时失败，MUST NOT 覆盖或清空任何既有文件。

#### Scenario: 目标已存在
- **WHEN** 用户尝试在已存在文件的位置新建笔记库
- **THEN** 操作失败并提示更换文件名，原文件内容不变

### Requirement: schema 迁移

迁移 MUST 按版本顺序执行，每个版本 MUST 在单个事务内完成；任一版本失败 MUST 整体回滚并保持可再次启动的状态。

#### Scenario: 迁移中途失败
- **WHEN** 某个迁移语句执行失败
- **THEN** 该版本的所有变更回滚，库版本停留在失败前，应用报告错误而不是继续运行

#### Scenario: 重复启动不重复执行
- **WHEN** 同一版本的程序第二次启动
- **THEN** 已应用的迁移被跳过，数据不变

### Requirement: 备份与迁移数据

备份 MUST 生成与当前数据一致的单文件快照，MUST NOT 覆盖已存在的目标文件。切换笔记库路径 MUST 通过生成快照后打开新路径完成，失败时 MUST 保留原路径与原数据可用。

#### Scenario: 备份不覆盖
- **WHEN** 目标备份文件名已存在
- **THEN** 备份失败并提示换名，已有文件不被修改

#### Scenario: 迁移失败可回退
- **WHEN** 迁移到新路径过程中失败
- **THEN** 配置仍指向原路径，原库可正常打开

### Requirement: 云同步目录约束

当笔记库位于云同步目录时，系统 MUST 提示同一时间只在一台设备写入，MUST 在检测到外部修改或锁冲突时给出可见错误，MUST NOT 在冲突后静默覆盖文件。

#### Scenario: 双设备同时写入
- **WHEN** 同一同步目录中的库被两台设备同时修改
- **THEN** 后写入的一方看到冲突提示，数据不被静默覆盖

### Requirement: 笔记库信息可见

设置 MUST 展示当前笔记库路径与基本统计（笔记数量、文件大小），并 MUST 提供备份入口。

#### Scenario: 查看当前路径
- **WHEN** 用户打开设置中的笔记库页
- **THEN** 显示实际使用的绝对路径、笔记数量与文件大小
