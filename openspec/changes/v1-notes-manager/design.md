## Context

仓库已有可运行的 Tauri 2 + Vue 3 + SQLite 骨架（提交 `f42ab93`、`1234a06`），产品范围与里程碑已由本 change 固化为规格。架构分层与代码级约定见 `docs/ARCHITECTURE.md`；本文件记录会影响后续任务的技术决策，不重复逐条实现细节。

约束：
- 仅 macOS 12+，Intel 与 Apple Silicon 都要能构建；不联网、无账号、无服务端。
- 单主窗口 + 菜单栏常驻形态决定了生命周期不能按「关窗即退出」实现。
- 数据是用户唯一资产，笔记库可被放到云同步目录，任何失败路径都不能静默丢数据。

## Goals / Non-Goals

**Goals:**
- 键盘优先：全局快捷键唤出 → 搜索/新建 → 编辑 → 自动保存，全程不需要鼠标。
- 数据可携带：单个 SQLite 文件，可备份、可换路径、可放同步盘。
- 行为可验收：每个能力都有可测试的规格与场景，测试计划与规格一一对应。

**Non-Goals:**
- 不做独立 Snippet 实体、快速面板、多窗口、第三栏（计划 §0 已排除）。
- 不做云同步服务、账号体系、协作编辑、移动端。
- 不做插件系统、主题市场、自定义 CSS。
- V1 不做加密库（笔记库不以加密为前提设计）。

## Decisions

**D1 单连接 + Mutex + `spawn_blocking`。** V1 数据量小且写入天然串行，单连接避免多连接写冲突与 WAL 调优；`spawn_blocking` 保证不阻塞 UI。备选：专用 DB 线程（消息队列）——并发上限更高，但需要额外请求/响应通道与取消语义，等搜索压测显示锁竞争再迁移。

**D2 迁移一版本一事务，拒绝降级。** `schema_migrations` 记录已应用版本；执行前比对程序支持的最大版本，磁盘更新则拒绝启动并提示升级应用。备选：自动向下兼容读取——会让新版字段在新库上被静默丢弃，风险更高。

**D3 乐观并发而非悲观锁。** 保存携带 `expectedUpdatedAt`，不匹配返回冲突。单用户桌面场景冲突极少，代价是冲突时必须给用户可见处理入口（当前 UI 呈现错误条，M6 任务补齐重载/覆盖选择）。

**D4 软删除。** `deleted_at` 非空即删除；所有列表/搜索/计数都过滤，FTS 投影同时移除。备选：物理删除 + 备份——恢复成本高，且误删是高频事故。

**D5 自动保存用防抖 + 串行队列 + 版本号。** 600ms 防抖降低写入频率，队列保证顺序，版本号防止旧响应覆盖新输入。备选：每次按键保存——写入放大且冲突窗口变长。

**D6 搜索先 LIKE，后接 FTS5。** 表与投影已建好并在写路径维护，M4 才把查询切到 `MATCH`。这样 M1–M3 不被分词问题阻塞，同时避免「先上 FTS 再补索引维护」导致的数据不一致窗口。最终实现见 D15。

**D7 窗口显隐集中到 `WindowManager`。** 快捷键、菜单栏、IPC、关闭按钮都走同一入口，内部加锁串行化，`visible` 只在成功后更新。备选：各处自行 `window.show()`——已证明会产生状态漂移与焦点丢失。

**D8 每次显示重新居中，只持久化尺寸。** 用户在多显示器间移动时，「上次位置」经常落在已断开的屏幕上；居中到鼠标所在屏更可预测。备选：恢复坐标——多屏场景失败率高。

**D9 偏好与数据分离。** 主题/强调色/字号/栏宽写 Tauri Store，笔记库只有笔记与标签。好处：换库不丢外观、备份文件不含个人偏好；代价是偏好不随库迁移。

**D10 备份用 `VACUUM INTO` 且不覆盖。** 得到一致性快照，不依赖 WAL 文件；目标存在即失败，避免误覆盖用户已有备份。

**D11 前端只有 `services/commands.ts` 触碰 IPC。** 组件与 store 不直接 `invoke`，DTO 与错误在单一位置规范化，便于后续换传输或加日志。

**D12 自定义路径失效时回退默认库并记录日志。** 直接启动失败会让用户连界面都看不到；但回退 MUST 在界面可见（`tasks.md` 5.6），不得静默把空库当成功。

**D13 迁移笔记库保留旧文件。** 迁移 = 快照 → 打开新库 → 原子改配置指针；旧库不自动删除，失败时可回退，代价是需要用户手动清理。

**D14 启动静默（待实施）。** 配置文件已是 `visible: false`，但当前在 `setup` 中主动 `show`，属于脚手架期的临时手段：首次启动若完全静默，容易被误判为没启动。目标行为是冷启动始终隐藏（`specs/macos-shell`），可发现性交给菜单栏与一次性提示（6.13）。

## Risks / Trade-offs

- **FTS5 中文分词**：unicode61 实测把整段中文（含标点中断的连续汉字）当成**一个 token**，`"笔记"` 短语匹配不到 `笔记管理的要点`，纯 LIKE 全表扫描在 10k 条时最差 106 ms（P95 超标）。落地方式见 D15。
- **置顶窗口干扰**：显示期间 `always_on_top` 可能遮挡用户正在看的其他应用，尤其在 Spaces 切换时。缓解：隐藏即取消置顶；M0 实机验收必须覆盖 Spaces/全屏/Stage Manager。
- **关闭即隐藏的认知成本**：用户可能以为已退出。缓解：菜单栏常驻 + 首次引导说明；M6 任务补齐。
- **自动保存在强杀下丢最后一次输入**：当前只在 UI 操作路径 flush。缓解：接入退出钩子与窗口隐藏前 flush；验收场景已写入 `notes-core` 与 `release-readiness`。
- **云同步目录双写**：SQLite 文件被同步工具并发替换会损坏。缓解：规格要求可见错误与单设备提示，不做自动合并。
- **后台常驻资源**：WebView 常驻会有基础内存占用；缓解：隐藏时不跑轮询、不跑定时器，M7 做 24h 驻留测量。
- **单连接成为长任务瓶颈**：大库备份会占用连接。缓解：备份在 `spawn_blocking` 中执行，UI 显示 busy 状态；若影响交互再迁移到 D1 的备选方案。

**D15 搜索 = FTS 粗筛 + 字面精筛，索引侧逐字展开中文。** `unicode61` 把连续汉字整段当一个 token，所以只靠 `MATCH` 无法命中词组中段；但只用 `LIKE` 又会在「罕见词/零命中」时退化成 10k 行全表扫描（实测 92–117 ms，P95 破 100 ms 预算）。
做法分三层：

1. **索引侧**：`search_index::explode_cjk` 在写入 `notes_fts` 前把每个 CJK 字符用空格隔开，于是「笔记管理」变成 4 个 token，任意连续字串都能用相邻短语命中。旧库由迁移 v3 清空投影 + Rust 侧 `reindex_all` 全量重建（否则老数据仍是单 token 格式）。
2. **查询侧**：`to_match_query` 只把「引号短语」和「前缀 `*`」交给 FTS 解析器——ASCII/数字按词首前缀（`sql` → `"sql"*`），中文按相邻字符短语（`管理` → `("管" "记")` 形式），FTS 运算符、引号、`%` 无从进入。输入没有任何字母数字时返回 `None`，调用方跳过 `MATCH`。
3. **精筛**：候选集仍要过一遍字面 `LIKE`（标题/正文/标签名），因为前缀查询会让 `100%` 的候选里混进 `1000`，词缀匹配也不等于字面包含。标签一律走 `note_tags`/`tags` 联表，**绝不**用 `notes_fts.note_id`（UNINDEXED）做相关子查询——那会把每次查询变成 O(n²)，实测 10k 条时 54 s。

权衡：中文与英文都是「字首/连续字符」匹配，不是任意 infix（搜 `lite` 不命中 `sqlite`）。字面精筛保证了不含假阳性，规格里把粒度写成契约（`sql`→`sqlite`、`管理`→`笔记管理的要点`），避免用 bm25 重排牺牲游标分页的稳定性。基准结果：P50 16.5 ms / P95 18.5 ms（10k 条，14.6 MB）。

**D16 预览 = 自建围栏切分 + 逐段 markdown-it + Shiki 按需高亮。** 每个围栏块要有自己的复制按钮，而 markdown-it 的 `highlight` 钩子只能返回 HTML 字符串，无法挂 Vue 组件；因此先用 `fences.ts` 按 CommonMark 围栏规则把正文切成「散文 / 代码」段，散文交给 `html: false` 的 markdown-it，代码段交给 `CodeBlock.vue`。

1. **围栏解析**：行扫描而非单个正则——闭合围栏必须同字符且不短于开围栏，反引号围栏的信息串不得含反引号，未闭合围栏延续到文末并按代码块渲染（规格要求「未闭合围栏仍可读且可复制」）。
2. **高亮**：`shiki/core` + JS 正则引擎（不加载 oniguruma wasm），42 种语言各自 `import()` 成独立 chunk，只在笔记里真的出现该语言时才下载；未知语言、空代码、超过 2 万字符、语法加载失败一律回 `null`，组件退回纯文本，绝不让整篇预览失败。
3. **配色**：Token 颜色直接用 Shiki 的 `github-light-high-contrast` / `github-dark`。原 `github-light` 的橙色字在 `--code-bg` 上只有 3.2:1，实测不达 AA；换高对比版后两种主题的所有 token 实测 ≥ 5.67:1。主题色从 settings store 的 `resolvedTheme` 取，切换深浅色时重新着色而不是重载笔记。
4. **链接安全**：`markdown.validateLink` 改为协议白名单（`http`/`https`/`mailto`/相对路径），先剥离控制字符再判 scheme，因此 `java\tscript:` 这类变体同样被拒；协议相对 `//host` 一律拒绝。预览的点击处理器统一 `preventDefault()`，只有 http(s) 交给系统 opener，避免 webview 被导航走。

权衡：切分让「代码块」不再是 markdown-it 的产物，两套解析规则必须保持对 CommonMark 围栏的一致（用 12 个单元测试锁定）；语法包按语言拆分意味着首次出现某语言时有几十到几百毫秒的加载与着色延迟，可接受，因为纯文本先行渲染。
